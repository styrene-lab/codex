# Portable analysis bundles

## Overview

Define portable research/analysis bundles as self-contained Flynt-shaped folders
generated by agents. A bundle packages source notes, citation metadata, claims
registers, analysis documents, tasks, Canvas explainers, and optional Eidolon
structured views so it can be opened as its own Flynt project or imported into
an existing project.

## Decisions

### Accepted: bundles are Flynt-shaped folders first

**Status:** 

**Rationale:** The first bundle format should be an ordinary folder of markdown, Canvas files,
Eidolon files, citation files, and manifests. A dedicated archive/package format
can come later if needed.

### Accepted: source notes remain canonical inside bundles

**Status:** 

**Rationale:** The bundle manifest organizes and indexes the investigation, but source truth
lives in `kind = "source"` markdown notes with flat frontmatter and durable body
sections.

### Accepted: claims registers are required for source-checkable analysis

**Status:** 

**Rationale:** Bundles that make analytical claims should include a claims register tying
claims to sources, confidence, and verification status. This enables review,
refresh, and citation-aware Canvas cards.

### Accepted: Canvas and Eidolon are complementary bundle outputs

**Status:** 

**Rationale:** Canvas provides curated explainers and dashboards. Eidolon provides deep
structured views for complex APIs, schemas, databases, ontologies, and large
relationship graphs.

### Accepted: capture method and access scope must be explicit

**Status:** 

**Rationale:** Bundles must distinguish public web fetches, browser captures, file imports,
manual notes, and Zotero/imported citation records. The agent must not blur
captured evidence with inference.

## Open Questions

- [assumption] A bundle can be represented as a normal Flynt-compatible folder before adding a dedicated archive/package format.
- [assumption] Bundle import should be non-destructive and preserve original relative paths where possible.
- Should the top-level manifest be named bundle.toml, flynt-bundle.toml, or .flynt/bundle.toml?
- Should bundles require .flynt/config.toml to be directly openable, or should Flynt infer project defaults when opening a folder with a bundle manifest?
- What is the minimal citation export set for v1: CSL JSON only, BibTeX only, or both?
- How should source refresh behave when a bundle is imported into a larger project with its own source notes and duplicate sources?
- Should bundle import create a namespace folder such as research/<bundle-slug>/ by default?
